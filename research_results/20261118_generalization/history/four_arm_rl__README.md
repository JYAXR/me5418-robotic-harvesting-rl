# 准备模型：四组强化学习续训对照

四组均从同一个旧场景33/33的准备模型完整状态出发。原模型和项目核心文件不修改。无新增规划器示范，无人工动作纠正，无新网络或坐标变更。

## 预先固定的方案

| 组别 | 原奖励之外的改动 |
|---|---|
| control | 无；仅进行相同预算的在线续训 |
| stagnation | 完全无效的动作额外扣0.3：机器人位移小于1e-6，且枝条节点最大坐标变化也小于1e-6 |
| damage | 损伤时额外扣50，相当于损伤惩罚由50增到100 |
| noise | 执行位移的两个坐标方向各加入均匀随机扰动，上限为当前命令步长的10%；奖励不变 |

- 从 `experiments/retention_rebuild_20261118/results/run01/preparation/prepared_state.pt` 恢复网络、目标网络、Adam及更新计数，而不是从零开始。
- 所有组保持学习率1e-4、gamma=0.99、目标网络每200次更新同步、梯度范数上限10。
- 训练场景：原33个＋新增33个（2026113000–2026113032），共同固定打乱顺序，每个场景分配200次实际交互，共13200次/组。
- 提前成功或损伤后，重置同一训练布局用完该场景配额。没有结束的片段在切换布局时不伪造任务终止。
- 随机动作探索率由20%逐渐降至5%。所有组预先使用同一份随机动作位置和随机动作编号。
- 64次交互后，每4次交互更新一次，3285次更新/组。此预算是有限试验，不是充分收敛保证。
- TD批次：32条普通在线经验、16条困难在线经验、16条原有示范经验。困难经验来自受阻或损伤前的短窗口。
- 保留原有示范复习约束：每次抽取64条旧示范计算动作margin，已有5个关键状态权重为2，保留已有恢复标签；不新增标签。目标为0.5×TD损失＋旧示范margin＋已有恢复margin/117。这是示范辅助DQN续训，不宣称纯无示范RL。
- 噪声只在实际执行时开启；场景生成与可行性检查保持无噪声，避免噪声组被生成器悄悄换成另一批更容易/困难的布局。
- 各组在4400、8800、13200次交互保存检查点、完整优化器状态、随机状态、在线经验及日志。只比较预定最终模型，不根据测试结果挑中间检查点。

## 评估

1. 原33个场景：检查遗忘。
2. 全新100个无噪声场景（2026114000–2026114099）：比较真正学到的策略。四个最终模型及未续训的准备模型都参与。
3. 上述新场景的前20个，各用3份执行噪声随机流重复：5个模型统一加入10%执行噪声，共300次诊断。60次/模型只涉及20个独立布局，不应称为60个不同场景。

评估均使用原奖励、200步上限、贪心动作，无在线更新或人工纠正。两种评估条件分开报告。每个条件逐场景检查五个模型初始状态指纹一致；所有失败保留。重载五个模型，各复跑一个无噪声和一个带噪声案例，要求轨迹完全一致。

场景种子在运行前与已有项目文本记录检查冲突；协议冻结源文件和模型哈希。全新测试只在四组训练完成并固定模型后开启。一个训练随机种子的试验不能证明普遍有效；不自动覆盖或提升默认模型。

## 执行

在项目根目录、原依赖环境中运行：

```bash
python -m pytest -q experiments/prepared_rl_four_arms_20261118/test_study.py
python experiments/prepared_rl_four_arms_20261118/study.py --phase train
python experiments/prepared_rl_four_arms_20261118/evaluate.py
```

中断后重复训练命令会从最近完整检查点恢复。已完成的组按哈希校验后跳过。预执行测试使用旧训练场景，不使用新测试集。

## 新增文件

- `study.py`：固定协议、四组奖励处理、在线训练和断点恢复。
- `evaluate.py`：5个模型的匹配场景评估、带噪声诊断、统计及重载核验。
- `test_study.py`：训练预算/分集、奖励、完整状态恢复、单步更新、数据存取、噪声范围和初始布局一致性测试。
- `results/`：协议、模型、完整续训状态、每段真实经验、损失、评估初始状态和轨迹。
- `RESULTS.md`：完成后写入的中文实际结果。

本轮不包含400步上限实验，以免将执行噪声或奖惩的影响与放宽任务预算混在一起。没有修改原项目或推送GitHub。

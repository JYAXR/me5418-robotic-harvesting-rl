## 范围与训练预算

1. 重建相对位置准备模型：全1440示范，监督20000、回报校准20000、TD10000、定向修正2000次，共52000次梯度更新。
2. 重采集67个训练场景（1170000–1170066）的成功轨迹。
3. 两组均从重新得到的准备状态出发，各6000次更新。完整回顾旧33+新67场景，旧/新各占50%损失权重，各组内按场景均衡。
   - 联合组：margin、MC、0.5 TD同时训练。
   - 分阶段组：3000次margin、2000次margin+MC、1000次margin+TD。
4. 验证1181000–1181015；按成功数、较少损伤、较少总步数选点；同分选较早者，原准备模型也参与。
5. 全部选择冻结后，再跑原33场景和已用过的测试1182000–1182031。

本轮没有额外在线训练交互；环境执行噪声为0；DQN/MLP、相对坐标、奖励不变。
成功示范没有停滞，因此0.3停滞惩罚不改变所用示范的奖励。
每1000更新保留完整可续跑状态；阶段检查点保留模型和验证。不会按历史结果调整参数。

## 运行

在原项目根目录和已安装原项目依赖的环境中：

```bash
python -m pytest -q experiments/retention_rebuild_20261118/test_rebuild.py
python experiments/retention_rebuild_20261118/run.py --phase prepare
python experiments/retention_rebuild_20261118/run.py --phase collect
python experiments/retention_rebuild_20261118/run.py --phase trials
```

准备训练与数据采集可在协议创建后分别运行，它们写入不同目录；两组对照必须等两者完成。
重复执行同一阶段会核对输入和完整检查点后继续，不能绕过哈希不匹配。

与丢失版本相比，新增的是恢复调度、检查点密度和记录方式，不是新的优化超参数。
是否逐字节恢复原模型，以`historical_hash_comparison.json`为准。即便计数相同，
在哈希不同且旧权重不可用时，也不能宣称权重精确复现。
